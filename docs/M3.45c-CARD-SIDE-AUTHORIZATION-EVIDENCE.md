# M3.45c — Card-side authorization evidence

**Status:** Simulator-only research proof, not production security.

## Reproduce

Requires the pinned ZKNOX simulator build, JDK 17, and existing
JavaCard dependencies.

```sh
python3 -B tools/test_card_side_authorization.py
```

The test uses synthetic BabyJubJub signing material and generates
a fresh P-256 authorization issuer keypair. Its public key is
embedded in a temporary applet overlay. The private key stays in
a restricted temporary fixture and is deleted after testing.

## Validated behavior

M3.45c.4a passed 17/17 simulator checks:

- Raw RESPOND without authorization rejected and session disarmed
- Valid ECDSA permit accepted and BabyJubJub signature verified
- One-time permit consumption and modified permit rejection
- Foreign issuer rejection with fail-closed session handling
- Old session and replayed permit rejection
- Domain separation enforcement
- Explicit cancellation and nonce invalidation
- Chained signing rejected without separate authorization

## Security boundaries

The overlay is not integrated into production Keycard firmware.
The test process controls the synthetic issuer and approval inputs.

The experiment does not establish trusted Shell identity,
physical user approval, secure issuer provisioning, protection
against compromised host builds, firmware attestation, hardware
randomness, fault resistance, or real transaction authorization.

## Next milestone

Design a protected issuer-provisioning lifecycle and Shell trust
root. The transport host must be unable to replace the issuer key.

All hardware testing remains separately authorized.
